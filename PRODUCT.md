# Openers Performance Dashboard

## Product summary

Openers Performance Dashboard is a private, role-scoped web application for importing agent-hours CSV files and turning the active dataset version into trustworthy performance reporting. It combines operational analysis with the administration needed to manage access, teams, import history, and audit evidence.

## Users

- **Administrators** oversee company-wide performance, users, teams, permissions, import versions, and audit history.
- **Managers** monitor the agents and teams inside their active assignments.
- **Agents** review only their own active-version performance.

## Core jobs

- Understand current call activity, logged-in time, time allocation, and rates without inspecting raw CSV files.
- Compare performance within the viewer's authorized scope.
- Move from overview signals into truthful team and agent detail.
- Import, validate, preview, publish, reject, restore, roll back, or deactivate datasets without losing history.
- Manage users, invitations, mappings, teams, and permissions without widening access.
- Review human-readable audit evidence while retaining technical details on demand.

## Product mechanism

Every visible metric comes from one active import version and one server-enforced role scope. The application preserves the original import and its lifecycle so operators can understand which dataset is active, when it changed, and who changed it.

## Operating context

This is a high-frequency desktop operations tool that must remain effective on tablets and phones. Users scan dense information, filter large tables, and perform consequential administrative actions. Fast comprehension, stable geometry, visible state, and predictable controls matter more than promotional expression.

## Capabilities that must remain intact

- Authentication, password reset, and invitation acceptance
- Server-side route and action authorization
- Administrator, manager, and agent data scoping
- CSV validation, preview, publish, rejection, and search/filter/sort behavior
- Active import versioning, immutable import history, rollback, restore, deactivation, and authorized downloads
- User, team, membership, mapping, invitation, session, and permission management
- Audit logging and safe technical-detail disclosure

## Brand and voice

- Product name: **Openers Performance Dashboard**
- Voice: concise, calm, precise, and operational
- Prefer user language such as “import,” “agent performance,” “team,” and “active data”
- Explain consequential state changes before the action
- Keep technical identifiers and enum values secondary to human-readable labels
- Never copy the reference image's company name, people, or sample metrics

## Evidence and truth

The repository, local database, server authorization rules, tests, and generated import records are authoritative. The supplied dashboard image is a visual reference only. Do not invent customers, benchmarks, metrics, commercial claims, identities, or operational capabilities.

## Product principles

1. **Truth before decoration.** Every metric, status, comparison, and action must reflect real scoped data.
2. **Scope is visible and enforced.** The UI explains the viewer's scope while the server remains authoritative.
3. **History stays legible.** Active data and permanent import history are related but never conflated.
4. **Dense does not mean noisy.** Hierarchy, grouping, and progressive disclosure keep operational screens compact.
5. **Consequential actions are explicit.** Destructive or version-changing actions state their exact effect and require confirmation.
6. **Accessibility is part of correctness.** Target WCAG 2.2 AA, full keyboard operation, visible focus, semantic structure, and reduced-motion support.

## Success criteria

- Administrators can assess company-wide performance and data health quickly.
- Managers and agents see only authorized information and can understand their scope without internal terminology.
- Every visible control has a real destination, state change, or server action.
- Import and administrative workflows preserve all existing behavior while presenting clearer hierarchy and feedback.
- All application routes share one responsive, accessible design system.
